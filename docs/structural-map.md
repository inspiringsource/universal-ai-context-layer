# Structural code map (experimental)

`aicontext pack` and `aicontext find` now include a compact structural map of
the shortlisted files, and `aicontext symbol` retrieves one definition's source
on demand. JavaScript, JSX, TypeScript, and TSX are parsed with Tree-sitter;
Python keeps the existing `ast` analyzer. No model is called and nothing runs
in the background.

The aim is more accurate orientation with less unnecessary reading. The local
evaluation below shows better symbol location at roughly equal total
characters; it does **not** show that an agent finishes tasks better or uses
fewer tokens. That remains untested.

## Commands

```bash
uv sync --extra dev                      # installs tree-sitter and both grammars
uv run aicontext pack --task "join a base URL with a relative path"
uv run aicontext find "retry policy" --limit 4
uv run aicontext symbol lib/helpers/combineURLs.js::combineURLs
uv run aicontext symbol src/payments.ts::RefundService.process --context 3
uv run aicontext symbol PaymentService.fromEnv     # unique name across the index
uv run aicontext symbol src/payments.ts --list     # every symbol and import of one file
uv run aicontext symbol lib/core/Axios.js::Axios --max-lines 40   # or --full
```

`symbol` reads `.ai/navigation.json`, so run `pack` first. It accepts
`--root` like the checkpoint and evidence commands. Exit status is 1 for
unresolved, ambiguous, missing, unsafe, or unparseable references.

## Three kinds of information, kept apart

| Kind | Where it appears | What it means |
| --- | --- | --- |
| Syntax facts | `EXPORT`/`DEF` lines, `@start-end`, import specifiers, `PARTIAL PARSE` | Parsed from one file by Tree-sitter (JS/TS) or `ast` (Python). Exact for what the parser accepted. |
| Inferred relationships | `IMPORT a → b`, `CALLS`, `TEST-CANDIDATE`, `AMBIGUOUS`, `UNRESOLVED` | Specifier resolved to an indexed file by path rules; a call name matched to the declaration an import binds. **Not** verified execution flow, dispatch, or coverage. |
| Recorded conclusions | `## Working checkpoint` section; pointers labelled `cited by checkpoint record ID (agent-recorded)` | Written by an agent with `aicontext checkpoint update`. Never generated from code. |

Files cited in `refs` of current, unfinished checkpoint records (next action,
objective, progress, todos, constraints, decisions) are pinned first in the
shortlist (at most two) and labelled as recorded, separately from lexical
matches.

## What is extracted

JavaScript (`.js`, `.jsx`) uses the JavaScript grammar, which includes JSX.
`.ts` uses the TypeScript grammar and `.tsx` the TSX grammar.

- Declarations: functions and generators, arrow and function expressions bound
  to variables, classes (including abstract and class expressions), methods,
  getters/setters, class fields holding functions, interfaces, type aliases,
  enums, namespaces/modules, top-level or exported variables, object-literal
  methods bound to a name (`api.charge`), CommonJS `exports.x`/`module.exports`,
  `export default <expression>`, and Express-style route registrations whose
  last argument is a handler function (`ROUTE`-like `GET /path via app.get(…)`).
- Qualified names: `Class.method`, `outer.inner`, `Namespace.fn`,
  `RefundService.process.audit`. Duplicates in one file get stable ids
  `name#2`, `name#3`. TypeScript overload signatures (functions and methods)
  are grouped with their implementation's range.
- Signatures: modifiers, type parameters, parameters with types and defaults,
  and return types, whitespace-collapsed, at most 160 characters (110 in the
  entry) with an explicit `…`.
- Ranges: declaration line, end line, and a `doc_line` for directly preceding
  comments or decorators, so retrieval includes JSDoc.
- Imports: ES imports (`type`-only marked), re-exports (`export *`,
  `export { a as b } from`, `export * as ns`), `require("x")`,
  `import x = require("x")`, and literal `import("x")`; a non-literal dynamic
  import is recorded as unresolvable.
- Syntactic calls per declaration: identifier and member callees, `new X`, and
  capitalised JSX components (`<Button>`), at most 12 per declaration.
- Declarations inside comments, strings, and template literals are never
  reported (the parser does not see them as code).

Python symbols are unchanged except that each now also has an end line, kind,
signature (`ast.unparse`), and decorator start, so `symbol` works for Python.
Python calls are not extracted.

### Resolution rules

Relative specifiers try the exact path, then for `.js`/`.jsx`/`.mjs`/`.cjs`
the TypeScript source extensions (TypeScript importers try `.ts`/`.tsx` first,
as the compiler does), then `.ts`, `.tsx`, `.js`, `.jsx`, then `index.*`.
If two sibling files fit (`format.ts` and `format.js`) the import is marked
`AMBIGUOUS` with the alternatives; a directory `index` after a matching file is
not treated as a tie. `compilerOptions.baseUrl` and `paths` (single `*`
wildcard) from the root `tsconfig.json` or `jsconfig.json` are honoured,
including comments and trailing commas; `extends` is **not** followed and the
entry warns when that may hide aliases. Bare specifiers are reported as
packages and never resolved into `node_modules`.

A call is linked only when its callee's first name is an import binding of a
resolved file and that file (following up to three levels of re-exports,
including `import { X } from './x'; export { X }`) exports a matching
declaration. `Obj.member(...)` resolves to a declared member `Owner.member`
when one exists; otherwise the link is labelled `owner-only` (the member is
inherited, built in, destructured, or dynamic). Several matches are
`AMBIGUOUS`. There is no scope analysis: a local variable that shadows an
imported name is not detected.

## Budget and omissions

The entry keeps the existing guarantees: essential checkpoint text (objective,
next action, every active constraint, blockers) is never truncated, and `pack`
fails without writing if it cannot fit. After that, priority is: the first
three pointers plus the first file's first structure lines, optional checkpoint
detail, remaining pointers, then remaining structure lines. Only whole lines
are added. The footer reports `Structure lines: N shown, M omitted by budget`,
and a pointer whose structure lines were all omitted falls back to inline
`name:line` locations. Sizes are measured in characters (Python `len`); the
`→` and `…` characters are 3 bytes each in UTF-8, so bytes can exceed
characters slightly. No token counts are reported because no tokenizer was
used.

Per file the entry shows at most 5, 4, then 3 declarations, chosen by
relevance to the task: name matches count three times as much as words used
inside the declaration's body; declarations scoring below half of the best are
dropped. Test files show only name matches and no imports. IMPORT lines are
omitted for files already in the shortlist or named by `CALLS`; ambiguous or
unresolved imports are always eligible.

## Retrieval semantics

- `PATH::NAME` resolves an exact id (`name#2`), then an exact qualified name,
  then a unique `.NAME` suffix within the file. A bare `NAME` searches the
  whole index the same way. More than one match is an `AMBIGUOUS` error that
  lists every candidate id; nothing is guessed.
- The stored range is used only if the file's sha256 matches the index. A
  changed file is re-parsed and the symbol re-located (`fingerprint CHANGED`,
  with a refresh hint); if it is no longer there the error says where it was
  indexed. Deleted files are `MISSING`; files added after the last `pack`, or
  excluded, are `NOT INDEXED`.
- Paths are checked with the same repository-escape guard as the rest of UACL;
  symlinks are refused; `.ai/` (checkpoint, evidence, generated outputs) is
  refused with a pointer to `aicontext evidence show`.
- Default bounds: 80 lines and 6,000 characters, long lines cut at 300
  characters with a marker. Members of a nested symbol are retrievable
  individually; the enclosing class or function header line is shown for
  context.

## Processing cost

Measured on an Apple Silicon laptop (median of three in-process builds; the
previous version's figure is a single build; see
`benchmarks/structure-results.json`). Timings vary from run to run:

| Repository | Files indexed | Parsed symbols | Build (s) | Rebuild after one edit (s) | Previous version build (s) | Index on disk |
| --- | --- | --- | --- | --- | --- | --- |
| hono `08a023cb` | 456 | 3,022 | 0.83 | 0.83 | 0.35 | 1.18 MB |
| axios `c4303eeb` | 407 | 2,907 | 0.36 | 0.36 | 0.22 | 0.69 MB |

Tree-sitter parsing itself is about a quarter of the time; the rest is the
Python traversal. A full rebuild under a second for ~450 files did not justify
a cache, so there is none: every `pack` rebuilds everything, which notices
added, deleted, and renamed files and recomputes all relationships. The index
is compact JSON with one file record per line (about half the size of the
previous indented format for the same content).

## Dependencies and licenses

`tree-sitter~=0.25.2`, `tree-sitter-javascript~=0.25.0`, and
`tree-sitter-typescript~=0.23.2` are regular dependencies, locked in `uv.lock`.
All three are MIT; the py-tree-sitter extension also compiles three ICU UTF
headers under the Unicode/ICU license. Names, versions, upstream URLs, and the
full notice texts are in [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md),
which is shipped in the wheel's license files. ast-grep and Aider's repo map
were not used.

py-tree-sitter **0.26.0** was tried first and rejected: traversing
`adapters/aws-lambda/src/handler.test.ts` in hono crashed the interpreter with
SIGBUS/SIGSEGV when reading node properties after a walk, reproducibly; the
same script works on 0.25.2. The pin excludes 0.26.

### 1. Regex versus Tree-sitter extraction

Fixtures (`tests/fixtures/jsts`, labels in `benchmarks/extraction_expected.json`):

flagged as a parse error rather than reported as clean.

Real repositories (no labels; only definite errors counted as errors):

| | hono | axios |
| --- | --- | --- |
| Regex "declaration" hits / Tree-sitter declarations | 11,213 / 2,924 | 4,482 / 1,137 |

The regex counted every indented `const`/`let` as a declaration. Its import
pattern took specifiers from JSDoc examples (`import { handle } from './index'`
inside a comment created a false edge) and missed multi-line imports. Its
misses include `export default <expression>`, `export abstract class`,
multi-line `export const`, enums, and namespaces.

Remaining Tree-sitter limitation: hono's 8 partial files are **valid**
TypeScript that tree-sitter-typescript 0.23.2 rejects (generic call signatures
in interfaces, `export type * from`). Before recovery, `src/types.ts` lost 23
of 42 exported declarations. Declarations inside error regions are now
recovered by a line scan and labelled `RECOVERED by line scan in unparsed
region; range estimated` (37 in hono), and the entry marks such files
`parse partial`. Recovered ranges can be wrong.

### Interpreting the results

- **Improved:** extraction accuracy (methods, multi-line declarations, exports,
  no comment/string false positives, no JSDoc import edges), symbol location
  (4 → 14 of 24), and cross-module discovery through `CALLS` lines (files
  named 7 → 10 of 13 on cross-module tasks). Follow-up reading fell because a
  bounded definition replaces a whole file.
- **Not improved:** which files reach the shortlist (12 of 24 either way). The
  ranking is still lexical; four tasks were missed by every method (H7, H10,
  A3, A4), where the request's words do not occur in names or paths, and the
  scripted search found H4's file, which both UACL versions missed.
- **Cost:** the entry roughly doubled (about 1,800 → 3,300 characters per
  task). Total characters exposed are about equal to the previous workflow's,
  and lower than the scripted search. The reading rules are assumptions;
  agents may read more or less.
- **Not a clean held-out test:** after the first run, two design changes were
  made in response to these same tasks: file-level matching was changed back
  to declared names (an all-identifier version dropped expected files from 12
  to 10–11), and test files and repeated IMPORT lines were trimmed. The tasks
  were also written by the implementer. Treat the numbers as a development
  benchmark.

## Known failures and untested claims

- tree-sitter-typescript 0.23.2 rejects some valid TypeScript (see above);
  Flow annotations in `.js` are not supported. Files ending in `.mjs`, `.cjs`,
  `.mts`, or `.cts` are not indexed at all; `.d.ts` files are parsed as
  ordinary TypeScript. Vue/Svelte single-file components are not parsed.
- No scope analysis: shadowed imports, dynamic property access, dependency
  injection, callbacks, and inherited members are not followed. `CALLS` names
  a static binding, not what runs.
- Destructured exports (`export const { a } = obj`), `export =` of
  expressions, and re-exports of package imports are not modelled.
- `tsconfig` `extends`, project references, package `exports`/`imports` maps,
  and workspace packages are not resolved.
- Route detection is a call-shape heuristic (`x.get("/path", handler)`).
- File ranking is lexical; synonyms are not understood.
- **Untested:** whether agents read the map, follow `symbol` instead of
  opening files, finish tasks more correctly, or use fewer tokens or less
  time. No authenticated agent runs were made, and no paid runs were
  authorised. The comparison in [navigation-evaluation.md](navigation-evaluation.md)
  (fresh sessions with and without the map, identical code, request, model
  settings, and acceptance tests, counting map reading and every retrieval)
  is still required before claiming savings.
- Cross-agent use is a file/CLI workflow: any agent that can read Markdown and
  run a shell command can use it. Continuation has not been tested in Claude
  Code, Codex, or Gemini.

## Is further development justified?

Only narrowly. The parser-backed facts are clearly more correct than the
regex hints, and retrieval by `path::symbol` is a better unit of reading than
whole files. But the shortlist is no better at finding the right files, and
the entry costs more characters. The next step should be the live A/B run, not
more extraction: if agents do not use `symbol` and `CALLS`, the extra entry
text is cost without benefit, and the map should shrink back toward pointers.
